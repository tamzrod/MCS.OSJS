## Isolation and initial startup

- Four test-only services: `seed`, `mma2`, `modbus-simulator-runtime`, and `osjs-shell`; no container names, bind/production mounts, external data volumes, host networking, privileged containers or host-published Modbus ports. Unique project labels identify resources.
- The one-shot `seed` REFUSES any nonempty volume and creates ONLY disposable `listeners: []` and `devices: []` documents under this project's `verify-data`. This protection is essential. Start each new experiment with a NEW, empty, clearly owned project volume, not retained data; never reset or delete a volume to evade the guard.
- MMA2 is on an internal `verify-runtime` bridge. Simulator shares ONLY that test MMA2 container's network namespace for `127.0.0.1` readiness and Raw Ingest, never host localhost. MMA2's test-only container runs as root so its supervisor can write restart acknowledgments under this test volume, without privileged mode or any change to production images/config.
- OS.js is on a separate `verify-ui` bridge, connects through the test volume's Unix socket, and publishes only `127.0.0.1:18219 -> 18209`. Use only `VERIFY-SIM-1` with port `15020`, unit 1 INSIDE the test namespace. Missing-file `devices:null` behavior is not tested by this seeded fixture.
