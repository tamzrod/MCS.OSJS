# MCS.OSJS Identity Map

On invocation, the first question is **Who are you?** Resolve the answer from the actual agent/runtime identity, not the model's guess. If identity cannot be established, ask the operator and STOP before repository mutation. Identity is not task authorization.

| Identity | Role and workflow owner | May do | Must not do |
| --- | --- | --- | --- |
| OpenCode (local Ubuntu; Qwen) | Coding agent for an explicitly assigned ACTIVE CODE task | Read bounded context; edit task-allowed files; run declared targeted tests and bounded corrective retests; record evidence and state | Assume JR identity; run an ACTIVE TEST task as coding work; promote a successor; edit ICC; change task scope; approve its own independent TEST/VERIFY gate |
| OpenHands (explicitly assigned JR DEV or independent JR) | **JR DEV** for assigned CODE/DISCOVERY tasks and bounded workflow continuation; **independent JR** for separately assigned TEST/VERIFY tasks | As JR DEV: read bounded context; edit task-allowed files; run targeted self-tests/in-scope corrective retests; commit and non-force push the assigned task; perform bounded Git synchronization needed to deliver that task; record evidence; close the current already-promoted packet; and select/update the next already-promoted eligible packet for the **next invocation**. As independent JR: execute the exact TEST/VERIFY packet and return original evidence under `operation cwal.md`. | In JR DEV mode: self-certify independent TEST/VERIFY, change feature scope, edit ICC, force-push/destructively rewrite history, touch production/operator data, or execute a second product task in the same invocation. In independent JR mode: edit product source, repair failures, or self-authorize a packet. |
| ChatGPT (when assigned coding/workflow role) | Workflow author and reviewer | Prepare/promote tasks within explicit operator authorization; review independently obtained evidence | Invent a PASS, change ICC outside BLACK SHEEP WALL, or override a task boundary |
| BLACK SHEEP WALL | ICC context maintenance | Update ICC only under its own bounded directive | Implement product changes or independently promote tasks |
| Human operator | Promotion, permissions and exceptional operations | Authorize tasks, scope, environmental exceptions and merges | N/A |

All agents share `AGENTS.md`, `workflow/active_work/README.md`, task files and the same one-ACTIVE-task invariant. Platform adapters provide only tool/runtime mechanics; they cannot enlarge the identity's authority. OpenCode uses `workflow/adapters/opencode.md`. OpenHands follows `operation cwal.md` in the mode explicitly assigned by `handoff.md`: **JR DEV** for CODE/DISCOVERY or **independent JR** for TEST/VERIFY. A single invocation may use only one mode. Playwright is available only when the current task explicitly authorizes a safe browser target and exact actions.

Execution: IDENTITY -> IDENTITY MAP -> DIRECTIVES -> ACTIVE MICRO-TASK -> IMPLEMENT (CODE only, by OpenCode or assigned OpenHands JR DEV) -> SELF-CHECK -> DELIVER CURRENT TASK -> RECORD/CLOSE CURRENT STATE -> SELECT NEXT ALREADY-PROMOTED ELIGIBLE PACKET FOR A LATER INVOCATION -> STOP. Independent TEST/VERIFY is always a separate mode/invocation and never becomes part of the coding run. Selecting a successor is workflow continuation, not permission to execute it immediately. If task/queue/handoff conflict cannot be resolved from genuine current-task evidence and the already-approved queue, STOP rather than inventing scope.
