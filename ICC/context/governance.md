## Stable authority boundaries

- `AGENTS.md` routes the StarCraft directives and agent identity. Read the invoked directive's actual file; a cached ICC summary is not authority.
- `workflow/ICC_CONSUMER.md` is the shared **read contract** for repository-dependent CODE, DISCOVERY, Planning, Microtask and Brainstorm work, and it names the exception for each StarCraft directive. It is navigation and validity policy, not a new directive, execution permission or cross-directive invocation; it grants no mutation, environment or transport authority. Planning, Microtask and Brainstorm all route their ICC-first rules through it.
- `BLACK_SHEEP_WALL.md` alone defines ICC maintenance and alone owns ICC writes. Process v1 routes a direct invocation deterministically: BOOTSTRAP only when no usable map exists; UPDATE for a node whose own baseline/overlay is not current; REVEAL for required unmapped territory; REUSE when the node is current with no intersecting source delta; BLOCKED when a required comparison is missing. **After bootstrap, direct invocation means delta-driven incremental maintenance, never an automatic full repository audit.** This corrects the superseded rule formerly copied into this context.
- The same directive's process is machine-checked rather than prose-only: `scripts/check_icc_map.py` validates schema, reciprocal tree, routing, state claims and links without reading product source or writing ICC, and `scripts/icc_decision.py` implements the pure routing decision. Both are governance tooling, not product runtime, and a structural PASS is not product acceptance. THE GATHERING is explicitly forbidden to run the checker or otherwise certify the cache.
- `operation cwal.md` and the active task packet define bounded execution/test permissions. ICC cannot promote tasks, authorize code edits, invent evidence or advance workflow. Its delegation to BLACK SHEEP WALL is narrowed to an explicitly authorized bounded CODE/DISCOVERY context refresh; an independent JR test packet is not authorization to invoke BLACK SHEEP WALL, and a migrated `unverified` node is not an extra JR test gate.
- `handoff.md` and canonical workflow files supply continuation state; Planning and Brainstorm do not authorize implementation. A summarized task status belongs in `active-work`, not governance.
- Git/source is final authority for implementation facts; ICC is a cache. A conflict means verify and refresh the smallest affected semantic node, not blindly trust either cached prose or a different branch.
