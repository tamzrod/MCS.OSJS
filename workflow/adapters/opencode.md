# OpenCode adapter — persistent Ubuntu workstation / Qwen

## Permanent branch and environment — mandatory

OpenCode operates on the user's persistent workstation, NOT a disposable sandbox. Its sole authorized development branch is `opencode`. Before ANY task or edit, verify `git branch --show-current`, `git rev-parse HEAD`, `git status --short` and `git worktree list`. If current branch is not exactly `opencode`, STOP with the mismatch; never silently switch, checkout, reset, rebase, merge, clean, restore or stash to fix it. Do not implement on `main`, `osjt-*`, detached HEAD, or another agent's branch. Do not touch other worktrees. Preserve all pre-existing work; overlapping edits or an unsafe workspace => BLOCKED/STOP. Fetch/pull only when safe and explicitly requested; a pull must not overwrite local commits or dirty work. No automatic merging or conflict resolution.

## Transport boundary

Completion of a task does NOT require a GitHub push. Never push, force-push, merge into `main`, create a PR or publish a task commit without a separate explicit human instruction. A task may authorize a LOCAL commit of its own allowlisted changes and local workflow evidence; record its SHA. If a packet mentions routine push-on-completion, this adapter overrides it: retain locally and report `NOT PUSHED — by policy`. No task should be declared blocked merely because no push was requested. Do not commit at all when the packet is read-only/chat-only or does not authorize local commits. No global git reset, even for synchronization, without separate explicit approval and verified backups.

## CWAL routing — autonomous, one task per invocation

The operator's complete prompt is `pull latest and do operation cwal`. Treat OPERATION CWAL as workflow routing, NOT automatic JR identity. Read `workflow/IDENTITY_MAP.md`, `AGENTS.md`, `operation cwal.md`, `handoff.md` and `workflow/active_work/OTR_PROMOTION_QUEUE.md` as needed. The approved queue does not require another human task-selection prompt. Resolve the single assigned OpenCode CODE/DISCOVERY task from current handoff; on a later invocation select the first eligible queued successor only with genuine predecessor evidence and a complete executable packet. `ACTIVE`/`QUEUED` are scheduling labels, not second approval gates. If a packet is incomplete or evidence unavailable, report the precise blocker and STOP, never ask 'what would you like me to do?'. Parent OTR-004..014 templates are not executable children.

## ICC context for the selected CODE/DISCOVERY task

Follow `workflow/ICC_CONSUMER.md` **after identifying the one authorized task**, not as a way to search for another assignment. Read `ICC/INDEX.md`, the selected entry in `ICC/manifest.json`, and only the needed context node. Compare the selected node's own baseline/overlay/validity with the actual `opencode` checkout; historic `main` provenance and migrated `unverified` metadata are not proof of local freshness. REUSE if current and unchanged. Request BLACK SHEEP WALL only for a bounded REVEAL/UPDATE within the packet's semantic/source ceiling and only when that delegation and ICC-writing environment are authorized; it returns here without changing the task. If it is not authorized or cannot safely validate the cache, use only task-permitted authoritative source and disclose `ICC unverified`, or report the specific blocker when essential context cannot be established. Do not re-audit every migrated node, edit ICC directly, treat the cache as code/test proof, or require an independent ICC test gate for a valid CODE packet.

Execute exactly ONE task per invocation: read the packet, inspect permitted sources, perform only its authorized edits/actions and targeted self-tests, capture actual evidence, write local workflow state ONLY if explicitly permitted, report and STOP. STOP is a per-task boundary, not a requirement for human selection of the next eligible task. Do not self-trigger a second cycle or pretend a chat-only report is persistent repository evidence. On FAIL/BLOCKED do not advance. No ICC edits: BLACK SHEEP WALL alone owns ICC.

CODE and independent TEST/VERIFY remain separate. OpenCode must not act as OpenHands/JR or certify its own changes independently. No production YAML, services, devices, sudo, installs, downloads or other workstation side effects without exact packet authority. Preserve unrelated changes and never invent tests or completion evidence.
