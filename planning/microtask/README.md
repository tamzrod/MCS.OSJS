# Microtasks

This directory contains sized, independently verifiable work items prepared from approved planning.

## ICC-First Context Rule

Before repository-dependent creation, refinement, sizing or splitting, resolve the specific task question and semantic ceiling, then follow `workflow/ICC_CONSUMER.md`: read `ICC/INDEX.md`, the relevant node entry in `ICC/manifest.json` and the smallest required Markdown context. Validate **that node's** baseline, audited overlay and validity against the actual checkout, not an index-wide baseline or another branch. Migrated `unverified` is not `current` and does not require a global re-audit.

REUSE current unchanged context. If the needed node is stale, unverified or absent, request only a bounded BLACK SHEEP WALL UPDATE/REVEAL within the planning scope if authorized; otherwise use task-permitted authoritative source with an explicit unverified caveat, or report the exact blocker. Do not inspect unchanged source just to repeat discovery, edit ICC yourself or let BLACK SHEEP WALL authorize execution.

After context resolution, follow `rules.md`. Tasks here are not authorized for execution until human promotion moves them into `workflow/active_work/`.

For Toolkit migration: `UMIG-NNN` is ChatGPT CODE, `UMIG-NNN-T` is OpenHands TEST and `UMIG-NNN-V` is OpenHands VERIFY. Human donor approval and intrinsically verification-only tasks retain their existing IDs. Each task has its own file, acceptance gate and handoff; no test pass is inferred from coding.
