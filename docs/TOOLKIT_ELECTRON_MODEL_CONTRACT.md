## Proposed backend authority and wire contract — HUMAN DECISION REQUIRED

- Reuse the existing Simulator Unix-socket v1 framed JSON service for two NEW management ops (`mma-load`, `mma-apply`) instead of Windows IPC, a browser file writer, an HTTP config API or direct application access to YAML. The OS.js Toolkit WebSocket relay routes only a validated Memory namespace request; `mma-load` requires an authenticated session; `mma-apply` additionally requires a VERIFIED server-side manage-MMA capability. Existing `ws._osjs_client` is an authentication check, NOT proof of edit authorization. The CODE task must identify the supported OS.js session/capability mechanism first and deny mutating requests if unavailable; no blanket access shortcut.
- Keep a separate Toolkit shared-MMA contract/client and in-memory persisted snapshot for root fields. `mma-load` result: `{settings:{rbe?,access_events?,debug?},revision:<sha256>}` where revision is computed from the exact canonical effective config bytes under the shared lock. `mma-apply` payload: `{settings:<whitelisted root patch>,expected_revision:<loaded revision>}`; missing revision, unknown field, unsafe output or invalid body rejects WITHOUT mutation. Null explicitly removes a supported root setting; absent key leaves it unchanged. Bound framed messages at existing 1 MiB and correlate envelope v1/request_id; distinguish INVALID_REQUEST, FORBIDDEN, REVISION_CONFLICT, VALIDATION_FAILED, RUNTIME_UNAVAILABLE and APPLY_RECOVERY_REQUIRED with truthful text; no false completion stamp.
- The full read -> compare revision -> patch ONLY root whitelist -> validate entire effective MMA2 candidate -> commit -> issue restart request/await ack sequence must be serialized against EVERY Simulator and Replicator config writer, not merely guarded by a mutex inside one Go process. Proposed mechanism is one shared Linux host-volume lock with writer-wide adoption around each read/compose/commit/restart sequence; management reads take the same lock. A plain `mma2composer.Commit` alone does not serialize a cross-process transaction. Lock path/timeout/Unix permissions, crash release and compatibility with existing supervisor must be verified before shipping; if they cannot be established, do not enable the mutating op.
- Load/return a canonical effective per-device advanced projection in Go without silently persisting inherited defaults. For matching `(port,unit_id)`, hydrate omitted `policy`, `state_sealing`, `rbe` from effective config while retaining the raw device document and all extension data; validate identities and return explicit error if effective config is corrupt. Distinguish omitted fields from explicit `false`, empty rule arrays and null. Apply device changes through existing producer/composer transaction, not root settings apply. Duplicate must reassign RBE IDs without changing foreign devices.
- Under lock, preserve owners byte-for-byte for a root-only edit, retain all listener/memory IDs, unknown root/extension fields and other-producer configurations. Validate candidate with MMA2 Go authoritative complete config + RBE validation BEFORE any file/restart request. If validation fails, mutate nothing. If artifact write fails, restore prior bytes and report failure (existing composer rollback covers certain two-file failures; extend tests to full path). AFTER a committed config whose restart ack/readiness fails, do NOT claim a safe automatic rollback: return APPLY_RECOVERY_REQUIRED with durable previous/current fingerprint and safe operator reconciliation path; any compensating restart/rollback requires a separately proven procedure. Never report success before ack/readiness. Request just one restart on genuinely changed global config; no restart for no-op or read.
- Device and shared UI drafts must be separate; shared dialog close retains unsaved settings without apply, Discard resets only shared settings, Save has at most one correlated management apply. Concurrent clients receive REVISION_CONFLICT and reload/explicit user review; never auto-overwrite. No RBE output or access-events HTTP listener may be enabled or published until independent binding/auth/network-scope review. Display fields disabled/UNAVAILABLE with explanation meanwhile, leaving existing empty/disabled settings unchanged.

## Proposed COMMS evidence and degraded behavior

Go `replicator/manager.go` now returns device `name`, enabled/running, ordered `blocks` with function/start/count/index/cycles/last_poll and `network`, `tcp`, `modbus`, `mma2` observed state/outcome/error/time, plus aggregated `comms`. Validate v1 reply envelope via existing contract and status.name against currently selected persisted device, enabled/running and canonical block signatures/count/index. On missing schema, mismatched name/block, unavailable socket, malformed/future timestamp, stale last_poll/observed_at or disabled/stopped device, show UNKNOWN with truthful reason; never retain earlier green across new selection/reload/error/teardown. Define freshness per block from its persisted scan_rate_ms: maximum age `max(10 seconds, 3 * scan_rate_ms)`, reject timestamps more than 5 seconds in the future; compare observation timestamp AND response reception age. Require actual current-cycle evidence for OK; aggregate current block evidence with ERROR > WARNING > UNKNOWN > OK, never blanket four green from source OK. Network OK is successful TCP connect, NOT ICMP; failed connect alone => Network UNKNOWN; TCP/Modbus/MMA2 follow their separate backend outcomes. Activity pulse only for new valid success timestamp, respect reduced motion. Missing telemetry on an older backend stays UNKNOWN and requests backend update/restart, not success.
