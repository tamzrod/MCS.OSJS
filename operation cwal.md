## Single source of truth
Task lifecycle is its canonical location ONLY: `planning/microtask/` proposed; `workflow/active_work/` approved and unfinished; `workflow/archive/` finished with verified acceptance evidence and delivery. Never use `Status:` in packets, queue or handoff. A queue lists approved IDs, dependencies and optional role, but no mutable per-task status. Root handoff identifies approved queue and global constraints, never an ACTIVE task or copied progress. Any planning duplicate is non-authoritative. Existing legacy status lines are migration debt, not evidence of completion; do not obey them over canonical file location and real evidence.

## One invocation: answer every executable question
1. Enumerate every approved ID and locate exactly one canonical packet in active_work or archive. Verify archived completion against required evidence and delivery; an unsupported archive is an integrity obstacle for that task and its dependents, not a license to claim COMPLETE. Report missing/duplicate canonical files precisely; isolate affected tasks. Do not globally STOP for a task-local discrepancy if unrelated tasks can safely be selected.
2. For each active_work packet inspect Task ID, Blocker Task, Assigned Agent, Stage and required authority. A blocker is satisfied only by an evidence-verified archived packet. Classify obstacles in a run report: unmet dependency, missing evidence/authorization, wrong agent, unsafe task environment or conflicting canonical identity. No mutable task-status labels or duplicated queue checkpoints.
3. Pick the lowest-ID eligible task assigned to this runner. Execute its exact packet immediately, one task at a time; no execute/pause/next-task menu. Capture real evidence, acceptance, required independent verification and delivery. On verified success, an authorized coordinator moves its single canonical packet from active_work to archive with evidence reference, then rescans. If a task fails, is blocked or interrupted, keep it in active_work, record precise reason and skip retry for this invocation. Do not archive to clear the queue.
4. After each task or task-specific obstacle, rescan for the next independent eligible task. An unmet dependency blocks its dependents only. A missing build instruction for FMT-005 or a task assigned to another agent must not block independent permitted work. Never execute FMT-005 or FMT-008 under this migration/reconciliation request.
5. End when no eligible work remains for this agent, or a genuine global repository safety problem prevents reliable selection. Report EVERY approved ID exactly once: archived with evidence/delivery reference, or still active_work with exact reason and required actor/action. Distinguish previously archived from completed this invocation. State branch/HEAD and delivery status. Do not call the queue complete while work remains.

Do not infer authorization from location alone: approved packet scope, role, exact commands, dependencies and environment must also permit the action. A genuine global STOP means explicit human STOP or unsafe repository-wide ambiguity that prevents safe task selection; otherwise isolate BLOCKED tasks and continue.
