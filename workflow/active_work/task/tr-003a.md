# OTR-003B — OSJS Gateway Contract Mapping Task

**Status**: READY FOR EXECUTION  
**Stage**: ACTIVE TASK  
**Owner**: OpenCode  

---

## Objective
Map ModbusToolkit server socket contract operations to their corresponding UI/API consumers, documenting the gateway routing layer that bridges UI requests backend execution.

---

## Mappings

### Simulation Gateway (`modbus-simulator.sock`)

| Contract Operation | Backend Socket Call | Purpose |
|-------------------|---------------------|---------|
| `simulate:loadSimulation` | Connect to `modbus-simulator.sock`, send `{simId}` | Request simulation load from backend database |
| `simulate:applySimulation` | Execute `{opcode: 'sim_load'}`, read response payload | Apply loaded simulation to virtual PLC |
| `simulate:status` | Socket poll/status check | Verify simulator operational state |

**Design Notes:**
- Simulator status operation (`{opcode: 'sim_status'}`) exists in code but is not exposed via UI by design
- All simulation calls flow through Unix socket; no direct Electron→MMA IPC

---

### Replication Gateway (`modbus-replicator.sock`)

| Contract Operation | Backend Socket Call | Purpose |
|-------------------|---------------------|---------|
| `replicator:read` | `{opcode: 'tcp', write: { ... }}` | Push data to replicators from simulator state |
| `replicator:write` | `{opcode: 'tcp', write: { ... }}` | Write replication payloads (acknowledge incoming) |
| `replicator:suggest` | *(no backend match)* | Planning/coordination-only operation |

**Design Notes:**
- Replication write operations consume incoming replicator data
- Suggest operation has no backend implementation—planning/coordination only

---

## Infrastructure Endpoints

### Modbus Toolkit Server (`OSJS/src/packages/MCSModbusToolkit/server.js`)

Exposed sockets:
- `modbus-simulator.sock` — Simulation contract operations
- `modbus-replicator.sock` — Replication contract operations

**MMA Endpoint**: None MMA remains a passive diagnostics/status component via Electron's `runtime:get-status` handler.

---

## Evidence Summary

This mapping confirms that OSJS gateway contracts for simulation and replication are fully realized through Unix socket routing in ModbusToolkit. The only exceptions are:
1. Simulator status operation (intentionally hidden by design)
2. Replicator suggest operation (planning-only, no backend implementation)

All other contract operations have explicit backend routing targets in the ModbusToolkit server.
