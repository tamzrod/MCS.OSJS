## Approved decisions and implementation limits

1. Use the existing Go Simulator Unix-socket v1 service as the shared MMA manager for `mma-load` and `mma-apply`. No Electron IPC, browser YAML writes, new HTTP config endpoint or Windows installer permissions in OS.js.
2. Authenticated `mma-load`; `mma-apply` requires separately VERIFIED server-side manage-MMA authorization. Authentication alone is insufficient. Fail closed and do not expose editing if the OS.js capability mechanism is unresolved. The root `debug` setting may be editable only after authorization and full validation are implemented; any network-output fields remain disabled pending an independent safety approval.
3. All Simulator, Replicator and shared-manager writers must adopt one bounded crash-released cross-process transaction lock; revision/CAS, whole-config validation, foreign-owner preservation, restart acknowledgement and truthful APPLY_RECOVERY_REQUIRED after a committed but unacknowledged restart are mandatory. Do not invent automatic rollback of potentially live state.
4. Keep RBE TCP and access-event output listeners disabled/unpublished by default; enabling them requires a separate bind/auth/network-scope approval. The RBE v1 draft is NOT LOCKED and has no authentication, replay or production latency guarantee.

This is approval of a design, NOT approval to skip independently promoted CODE/TEST/VERIFY stages, run production services, touch operator data, remove legacy UI or cut over. Only BLACK SHEEP WALL edits ICC.

## Approved shared Go authority and failure contract

- Reuse local Go Simulator Unix v1 4-byte big-endian framed JSON service with two additional Memory-namespace operations only, never a generic arbitrary-file edit. `mma-load` needs authenticated Toolkit session; `mma-apply` also needs real manage-MMA capability checked by the Toolkit server, and must reject without mutation when unavailable. `ws._osjs_client` proves authentication, not editing permission. Browser must never supply trusted identity.
- `mma-load` returns `{settings:{rbe?,access_events?,debug?},revision:<sha256 of exact effective config bytes>}`. `mma-apply` requires `{settings:<root whitelist patch>,expected_revision:<loaded revision>}`; missing/stale revision, unknown key, invalid/unsafe output, malformed input => no change. Null means removal and absent means unchanged. Keep correlated v1 `request_id`, 1 MiB cap and typed INVALID_REQUEST, FORBIDDEN, REVISION_CONFLICT, VALIDATION_FAILED, RUNTIME_UNAVAILABLE and APPLY_RECOVERY_REQUIRED; no false completion timestamp.
- Adopt a single shared host-volume Linux lock around FULL read/compare/compose/validate/commit/restart-ack across EVERY Simulator, Replicator and shared manager writer, plus shared management reads. Prove bounded wait, crash release, permissions and no nesting deadlock. A per-process mutex or `mma2composer.Commit` alone is insufficient. Until proven, disable `mma-apply`.
- Under lock, preserve owners unchanged for root-only edit, all foreign memories and listener IDs/listen/metadata and unknown extensions. Use authoritative Go MMA2 + RBE whole-config validation BEFORE any write; failed validation changes zero bytes. Restore original bytes for a partial artifact write. A committed config with failed restart acknowledgement/readiness returns APPLY_RECOVERY_REQUIRED and durable previous/current fingerprints for explicit operator reconciliation; no unproven automatic rollback. No restart for reads/no-op, and no success until acknowledgement/readiness.
- Go canonical Simulator load projects omitted policy/sealing/RBE from effective config by `(port,unit_id)` WITHOUT persisting projection. Explicit false/empty/null must remain explicit; corrupt effective config errors instead of silent defaults. Existing producer composer owns device apply, shared manager owns root edits only. Duplicate remaps globally used RBE IDs without changing foreign-owned devices. Shared modal uses separate draft/persisted snapshots; Close retains draft, Discard resets only shared, Save sends one revision-checked apply; on conflict require user reload/review.
- Global RBE TCP and access-events listeners remain off/unpublished, with editing of unsafe output fields disabled and explained until independent safety approval. No implicit port, customer/production enablement or network exposure.

## Approved COMMS telemetry semantics — no fabricated green

Validate existing v1 reply envelope, selected persisted device name, enabled/running, ordered block index/function/start/count against canonical Pull Blocks. Missing/legacy schema, wrong device/block, unavailable socket, stale selection, stopped/disabled runtime or transport error => UNKNOWN. Per-block last_poll/layer observed_at must be parseable, within `max(10 seconds, 3 * scan_rate_ms)` age, and no more than 5 seconds into the future; check reception freshness too. Per-layer OK requires actual current-cycle evidence, never infer all green from `source_status: OK`. Aggregate ERROR > WARNING > UNKNOWN > OK across current blocks. Network OK means successful TCP connection only, not ICMP; failed connection leaves Network UNKNOWN. Real Modbus exception WARNING, TCP failure and MMA2 Raw Ingest ACK govern their own layers; skipped write is not OK. Show endpoint/error/time in tooltip; pulse only for new valid success stamp and honor reduced motion. Clear stale green on selection, reload, error and teardown.
